# Separate successor exploration — not fixed-D Forward OOS

The existing research audit now calls `jra_bvi_successor_research.run`. The existing postresult workflow persists this directory and uploads it even after failures. No schedule is added or changed. This extension is not active on main until the Owner approves integration.

The adapter rechecks every dedicated Collector file's original raw/content hash and inherited admission clock. It reconstructs the dedicated population, excludes non-JRA venues, mixed/unknown surfaces and explicit named jump races, and retains the limitation that negative marker screening is not a complete official flat-race classification. Composite identities are not permanent IDs; repeated runs are not independent offspring.

A separate protocol evaluates two chronological folds using the unchanged existing estimator and coefficients fitting procedure. GENERAL and ENV use identical rows, class/form controls, capture boundary and training interval. No hyperparameters are tuned. Each fold saves the full fitted model, exact dataset and train/test hashes. Horse, sire and date clusters are resampled separately for descriptive paired loss intervals; these are not multiway, multiplicity-adjusted or causal intervals. Overlapping folds are never pooled into a false independent sample. Historical records acquired later remain post-capture diagnostics, not point-in-time historical forecasts.

Any TEST MSE worsening causes non-adoption under the registered diagnostic gate. Otherwise the decision still requires data qualification and independent replication. The seven A–G hypotheses in the canonical audit remain seven untested quality-held protocols; one global exploratory comparison is not seven hypothesis successes. A separately fitted full-data model is retained as a reproducible research artifact even if rejected; it is not published, executable as a future override or automatically admitted to OOS.

Input checkpoints preserve the first observed acquisition clock across partial writes. Complete artifacts and records are immutable. Unchanged inputs reuse fitted models; cached fold errors/cluster intervals and all authority/status fields are recomputed. Parser, feature-rule, estimator and adapter code hashes enter candidate identity. A modified dependency starts a different diagnostic. No numerical policy, fixed-D model or bound file is changed.
