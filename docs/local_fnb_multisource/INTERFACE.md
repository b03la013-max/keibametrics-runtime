# FNB multi-provider private frontend — v0.1, 2026-11-03

Operational priority (Owner instruction, 2026-11-04): deliver an independently
classified REFERENCE from existing evidence while Formal adoption is pending.
Repair the first actual failure and reuse the current calculator, model,
Engine, Selection and store. New predictive models, coefficients, policies,
Authority layers and duplicate execution services are frozen. Judge progress
by prestart complete predictions, user-visible delivery and later settlement.
This process change grants no Production, source, signing or purchase scope.

The existing `local_fnb_rakuten_reference.publish_saved_reference` adapter reads
verified 29-index/Static/KRS/S1/S2/R16 originals, compares a permitted current
card when supplied, and saves an unsigned REFERENCE body and manifest. Missing
formal signatures or formal Owner activation are not REFERENCE prerequisites.
It preserves UNKNOWN, original SOURCE/Freeze and every original ticket/stake.
Changed model inputs require a new immutable calculation revision; an unprinted
history direction remains unknown rather than being guessed. A failed parser
keeps the actual HTTP Raw so repair can be verified offline.

An existing private `FNB_PRODUCERS.py` may supply a `reference` callback returning
the exact indexed publication folder. R20 checks a saved signed completion
first, then reads the independent REFERENCE before repeating an unchanged
Formal attempt. An explicit Formal request still attempts Formal and can return
REFERENCE alongside its actual first failure. The normal entry's single
`read_saved_reference` consumer owns body/Race/all-horse/time checks; a trusted
binding need not repeat those same checks. Source capture, Owner, Engine,
Selection, signing and notification are never invoked by frozen readback.
The URW ordinal compiler and URW-only identities are not reused as FNB scores.

Reuse the existing request, SOURCE and adoption artifacts as the execution
context; do not add another context/Profile/Authority service. Formal's source
authenticity, Active, time, signature, Owner scope, numerical, KRS, MEC/Capital
and actual-array checks remain at their relevant trust/publication boundaries.
Natural scheduling, user acknowledgement and Formal acceptance are measured
separately from a saved or displayed REFERENCE.

This is a research integration interface, not an enabled Provider or an adopted
numerical/Owner policy. Current Production SOURCE, Consumer, signer, Runtime,
URLs and deployment remain unchanged.

`runtime.local_fnb_multisource.acquire` requires a separately admitted private
`ProviderBinding`: exact observed URLs, actor, permission evidence, validity,
private retention/cloud scope, pinned transport identity, real fetch callback
and source-specific parser. No invented provider HTML/CSV parser is included.
The callback is the existing approved origin/rate/robots transport; it must
return original HTTPS GET response bytes and its policy receipt. Search
snippets and browser DOM do not satisfy this interface. Capture is checked
against a fresh post-fetch clock, not request-start time.

Field output preserves Provider authority, URL, original SHA, capture/effective
time, Race identity, missing values and a separate rule-consumer decision.
Permission to fetch is not permission to consume a numerical Rule. Without a
separate exact `consumer_verifier`, every parsed field stays Tier 3. Vendor
`external_*` indices always stay Tier 3 regardless of the permission record or
rule name. No packet emitted here claims signed official Admission, Active
verification, Owner authority or registered OOS.

`acquire_available` tries each distinct Provider/URL once. An unavailable
binding or failed policy is a visible HOLD and does not prevent a separately
qualified Provider from being checked. It does not choose another origin to
circumvent the failed origin, silently retry or infer permission from public
availability.

`import_user_reference` reads the exact uploaded JSON bytes under their expected
SHA and unchanged reference classification. In the supplied FNB2R material,
NANKAN's 14-digit `program` URL is a day program, not proof of Race 2. The
Rakuten zero-filled RACEID is an unresolved alias. Neither suffix is parsed into
an authoritative Race ID. The reference JSON's Race identity is retained only
as a reference claim; provider_raw_sha is null.

`reconcile` joins only the claimed Venue/date/Race, reports field conflicts and
per-runner reference/supplemental/missing coverage. It never majority-votes,
resolves a current official value, marks an Active universe verified, or merges
same-named horses into permanent identities. Actual Provider parsers and the
existing official admission/verifier must independently check header/date/
post/distance/surface/horse number and provider permanent IDs before use.

`r20_source_frontend` is a callable for the existing
`FNB_PRODUCERS.py -> get_producers()['source']` interface. It requires an actual
qualified official producer and its independent source-admission verifier.
Absent either, it raises `MULTISOURCE_FORMAL_PRODUCER_NOT_CONNECTED`. The
verifier must bind its PASS to the exact official source artifact SHA.
Supplemental receipts are stored separately and never rewrite the official
SOURCE, so existing R13/R20 raw reparse, prestart, Owner qualification, KRS and
model-independence gates remain in force. This module cannot make NANKAN,
Rakuten, SPAIA or reference data into a NAR card or issue a signature.

Activation requires the real per-provider permission/actor/transport/parser and
current Consumer records. No such records are generated or adopted by this
change. Rollback: stop calling this optional frontend; retain immutable private
receipts and existing R20 source binding. No resources, keys, original
predictions or Production policies need deletion or rewriting.


## Prospective alternative Provider / single Owner transport — R17

The existing R20 private binding loader remains the entry. An installed
`FNB_PRODUCERS.py` must match `KM_FNB_PRODUCER_BINDING_SHA256`; its
`get_producers()` may opt into `FNB_ALTERNATIVE_PROVIDER_SINGLE_OWNER_V1`.
This mode preserves the separate legacy official-NAR / two-Owner contract.
It never falls back to NAR, imports an extra model or grants FNB Production.

`source(intent, private_root, now)` returns actual `raw: bytes`, HTTP `capture`,
the exact dated `request`, `actor_id`, and independently obtained qualification
originals. A bounded public-card producer is provided, with exact previously
observed URLs,61-second origin rate guard and no refusal/redirect bypass.
Its default output is reference-only. The callback's existence or HTTP200 is
never SOURCE admission. An installed source callback may instead supply a
separately admitted source packet with all original receipts below.

The adapter replays original Rakuten HTML without marking it NAR/official.
An admitted artifact uses `KM-FNB-ADMITTED-ALTERNATIVE-SOURCE-v1` and
`ADMITTED_ALTERNATIVE_PROVIDER_HTTP_CARD`. It must be in an actual SOURCE
envelope verified by the existing LOCAL Ed25519 key, with:

- exact raw/parsed/SOURCE SHA, URL, request/Race/date/post and capture time;
- actual permission original SHA and Provider/Actor/method/retention/Cloud
  scope, effective time and qualified field-Consumer adoption;
- actual current-change original SHA, complete declared IDs and signed
  ACTIVE/CANCELLED/EXCLUDED rows, current jockey/load and Active SHA;
- freshness/source Freeze before the300-second prediction cutoff.

Field admission covers identity/post, runner/frame, jockey/load, changes and
Active, bodyweight, weather/going and dated histories. A parser/receipt cannot
invent permission or an Active state missing from a qualified original.
Source identity and old signed receipts are preserved; no key is created.

The separate `owner_adoption_envelope` must verify as `OWNER_ADOPTION/APPROVED`
under existing LOCAL trust, bind one fixed FNB Owner and all four numerical
Consumers, exact frozen Model/Profile/Selection Module SHAs, source-admission
decision, numerical Registry/map bytes and prospective dates/Races/effectivity.
No current KAW-only Production Profile or global false flag is changed.

`execute_single_owner` concretely reuses the existing29 arithmetic, Context
Owner, HSV bridge,5000/seed1 Engine, S2/R16, strict Pair MEC, Capital and tree
renderer. Numeric/Static research-origin labels remain audit provenance; their
formal consumption needs the above exact adoption. A new execution has a new
Source/Race/Static Freeze. Old R16 PAPER is not renamed formal or OOS.
Missing adoption/signing fails before an Engine call. Each method retains full
semantic coverage; existing Capital independently chooses selected arrays.

The FINAL envelope is independently signature/SHA/Active/model/clock checked.
The single-Owner body includes all29, roles/UNKNOWN, KRS and all selected
method trees. A verified return is a saved Formal original, not Delivery.
The existing day supervisor performs actual recipient/original/ACK checking.
Delivery requires separately adopted recipient/route activation and real
`authorize_delivery`, `deliver`, `inspect_delivery`; send success is not ACK.
Durable claims stop blind repeated KRS or sends. No new permanent Worker is
created. Until real adoption, qualified SOURCE and recipient proof exist,
actual LIVE/natural execution/recipient Delivery counts remain0.

Readback recomputes Raw→existing29→fixed Static→the exact existing PRE_KRS
input, then S2/R16/MEC/Capital using the stored actual KRS output. It does not
run a second Engine. Callback flags and even a signed inconsistent artifact
cannot replace these comparisons. The complete rendered body is compared
with canonical content, including all roles and29 cells. All connection
module bytes must equal the separately adopted hashes; drift fails closed.

After a successful verified save, the private intent index points to original
source/qualification/execution bytes with SHA checks. The next invocation
reads that signed frozen revision before any source or Engine callback.
Delivery uses the current clock, cannot extend Cutoff, and requires actual ACK
originals matching Revision, Source, body, recipient/route and every method's
Ticket SHA. Manual Work execution never asserts natural activation. No
connection/signer/permission is supplied by default.

This is a prospective, unadopted contract. In particular the300-second cutoff,
600-second maximum SOURCE age and the admitted fields must be expressly
accepted in the exact source/Owner decision before formal use. Existing
Production policies/keys are unchanged. No feature can manufacture a Provider
qualification original, signed Owner decision or recipient-side acceptance.

`day_callbacks()` bridges the same qualified single-Owner originals into the
existing `local_fnb_day_supervisor`/finite Actor. It requires real discovery
and authorization callbacks supplied by the existing environment. Its new
completion type is independently reread and signed-source/Static/Selection
replayed by the supervisor; the legacy nonProduction completion verifier is
unchanged. No two-Owner requirement is added. ACK inspection reuses the same
private delivery claim and never creates a second send. Actual dated
activations/finite leases still require their real approval and file pins.
