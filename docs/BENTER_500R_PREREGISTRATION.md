## 3. 主系列・副系列と欠測

主比較相手は公式の最終単勝オッズ、副比較相手は署名前の最後の公式観測とする。
両方ともActive集合内で逆数を正規化する。両系列の比較は完全に同一の凍結Race集合で行う。
最終価格の判定には明示的な公式最終表示・Race照合・Raw由来の証拠を要求し、
取得時刻が発走後という事実だけ、人気順位、勝ち馬の払戻から価格を補わない。

主判定には、到達日で凍結した全適格Raceの確定価格が必要となる。
不足・改変・出走集合不一致・最終性未証明が1Rでも残る場合は
`INCOMPLETE_PRIMARY_CLOSING` とし、主判定をHOLDする。
取得済み共通部分と署名前系列の数値は記述統計として報告できるが、
署名前の合格で確定系列の合格を代用したり、後続日を足して不足Raceを置き換えたりしない。
同じ凍結集合の価格を後日補完した場合、取得時刻と新しい入力manifestを残し、元出力を上書きしない。
取得不能は取得不能として残す。後日取得時刻は当時の市場締切時刻ではない。

取得権限は別管理である。本承認の確定価格取得は2026-10-11〜11-01の対象178Rだけ。
500Rまでの後続開催日や自動収集は本書で承認しない。

## 4. 推定量と分割

市場M: `P ∝ exp(beta * ln(m))`。
モデルF: `P ∝ exp(a * z)`。zはActive集合内のZAI_WINをddof=0で標準化した値。
結合C: `P ∝ exp(a * z + beta * ln(m))`。
いずれも条件付きロジットの最尤推定。主モデルのa、betaに罰則や符号制約を課さない。
`LL0 = sum(log(1/n_active))`、`rho2 = 1 - LL/LL0`、`delta_rho2 = rho2(C)-rho2(M)`。

### 時系列前後半

Frozenの発走予定時刻、race_idの順に並べ、前半で学習・後半で評価する。
分割は現行Phase 0のstrict temporal splitとし、同時発走を学習と評価に跨がせない。
分割日や比率を結果に合わせて変更しない。

### 開催日ウォークフォワード

各JST開催日DはDより前の全対象Raceでのみ学習し、Dを評価する。
初日など事前学習がない日は評価しない。日ごとの対数尤度を合算し、
評価Race全体のLL0で累積rho2とdelta_rho2を計算する。日ごとのdeltaの単純平均にはしない。
主判定には両分割を同時に用いる。

## 5. 再標本化・対照・合格条件

以下を固定し、判定値を見てseedや回数を変更しない。

| 項目 | 固定値 |
|---|---|
| 乱数生成 | numpy Generator / PCG64 |
| master seed | 20261103 |
| レース単位paired bootstrap | 1,000回 |
| 95%区間 | bootstrap分布の2.5%、97.5%点（numpy linear quantile） |
| レース内シャッフル | 9,999回 |
| シャッフル片側p | (1 + null >= observed の回数) / (9,999 + 1) |
| 主対照 | それぞれのOOS分割のシャッフルdelta分布の95%点 |
| 二次13検定 | Holm step-down、片側alpha=0.05 |
| 正則化候補 | 0.0001, 0.001, 0.01, 0.1, 1, 10, 100, 1000 |

主95%区間は、既に事前学習済みのM/Cによる同じ評価Raceの対数スコア差を、
Race単位でpaired復元抽出する条件付き区間とする。WFでも、その日より前で推定した
予測のスコアを使用する。未来データで過去日の係数を更新しない。
学習集合も再抽出して再推定する区間は補助として別掲し、主区間と混ぜない。

対照では対象のzを各Race内で独立にシャッフルし、Mは同じ市場データの推定を使用、
Cは各学習区間だけで再推定する。WF対照も各日の学習が過去日限定となるよう構築する。
シャッフルseed系列は主ZAI_WIN=master+100、13指数は固定順のmaster+1000+列番号、
bootstrapはmaster+200とする。固定列順はHPI, SSI, CFI, RFI, JTI, CSI, TRI, BWI, GCI, PRI, KGI, BVI, VMI。
200回対照ではHolmの最初の閾値に達しない問題を避けるため、500R検証では9,999回に固定する。

**主合格は、確定価格系列について、時系列後半と開催日WF累積の両方で、
95%区間下限が0を超え、かつ観測deltaが対応するシャッフル95%点を超える場合だけ。**
いずれかが満たされなければ不合格。必要データ不足・収束失敗・手順未実装は判定不能とし、
統計的な不合格とは分ける。副系列や二次分析の良い結果で主判定を上書きしない。

## 6. 副次分析

- 13指数それぞれについて、同一集合・同一分割で単独rho2、市場上積み、区間、対照、
  片側p、Holm調整pを報告する。指数を結果で選別せず13件を一つの検定族とする。
  VMIはmarket_rank / market_stability / market_mismatchを消費する市場由来対照である。
- F-joint13は市場共変量ln(m)なし、13指数をレース内標準化してL2推定する。
  VMIを含むため「市場から独立した情報だけ」とは解釈しない。VMI除外12指数版も補助表示する。
  ZAI_WIN単独Fとの後半rho2を同じ集合で比較し、現在の手設定重みとは尺度の差を明記する。
- lambdaは外側学習区間の内側開催日WFでのみ選ぶ。内側履歴が不足する場合はlambda=1。
  market込みの副次L2モデルを計算するときもbetaは罰則なし、固定beta版は学習内Mの値だけを使う。
- betaの全期間／前半／開催日推移、bootstrap区間を報告する。
  beta>1という観測だけで勝率・EV・Kelly・投資額へ変換しない。
- 全頭をプールした補助のオッズ変化対ZAI_WIN相関には、
  delta_ln_m = ln(m_closing)-ln(m_pre) とレース内zを使用する。
  Race内平均を引いたdelta_ln_mのPearson相関と、各Raceの重みを1/nとした相関を別掲する。
  記述統計に限定し、因果的な資金流入や主合否の根拠とはしない。

## 7. 実装上の残件（本書はSPEC）

現行`benter_index_diagnostics.py`にはclosing系列のCLI指定がない。
必要な改修は分析層だけのseries adapterであり、検証済みclosing captureから作った
同一Race集合のmを渡し、元FINALの13値・traceをそのまま読む。
Base13の事後再計算、SOURCE更新、古い署名の付替えはしない。
publicリポジトリへRawを除いたcaptureを保存する場合、現行ReaderのRaw再検証を省略して
検証済みと扱ってはならない。非公開Raw保管先からraw_sha256で解決し、同じRawを再解析する
オフラインadapterも必要となる。非公開Rawが失われた場合はRaw未検証として主判定をHOLDする。
WFの主bootstrap区間と再推定シャッフル、9,999回の実行証拠も現行の保存値とは別に必要である。
これらが未実装・未検収のまま500R PASSとはしない。

環境、numpy/scipy版、計算器SHA、入力manifest、候補全件と除外理由、
cohortと分割SHA、乱数設定、収束状態を記録する。ホスト間の浮動小数点末尾差を隠さない。
全頭の補完・DCR・UNVALIDATEDは別監査とし、数値が存在するだけで実測完成100%と呼ばない。
